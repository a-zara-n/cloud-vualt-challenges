つきましては、御社にクラウド環境のセキュリティ調査をご依頼申し上げたく、本書面をもってお願いいたします。

## 4. 調査の目的

1. **クレデンシャルの漏洩状況の確認**: 対象企業のシステムから漏洩している認証情報がないかを調査する
2. **クラウド環境の脆弱性の特定**: IAM 設定、S3 バケット設定、各種サービスの構成を確認し、セキュリティ上の問題を洗い出す
3. **証拠ファイルの発見と復号**: 内部告発者が保管したとされる暗号化された証拠ファイルの所在を特定し、内容を確認する
4. **不正行為の全容解明**: CEO の不正取引に関する証拠を収集し、関与者の特定を行う

## 5. 調査上のルール

本調査は対象企業の協力のもと、法的に適正な手続きに基づいて実施されます。以下のルールを厳守してください。

### 5-1. 許可される操作

- AWS リソースの **読み取り操作**（describe, get, list 等）
- 公開されている GitHub リポジトリの閲覧・クローン
- 社員ポータルへのアクセスおよび機能の利用
- CloudTrail ログの分析

### 5-2. 禁止される操作

- リソースの **作成・変更・削除** 等の破壊的操作
- 他の参加者のセッションへの干渉
- 対象企業の本番サービスに影響を与える負荷テスト
- 調査範囲外のシステムへのアクセス

### 5-3. 証拠の記録

- 発見した脆弱性や証拠はすべて記録してください
- 各証拠には **フラグ**（`TVAULT{...}` 形式の文字列）が埋め込まれています
- フラグを CTF プラットフォームに提出することで調査の進捗が記録されます
